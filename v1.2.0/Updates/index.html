FixedPointToolkit.Updates

FixedPointToolkit.Updates.AndersonMixing — Method
AndersonMixing(VIn::N, VOut::N, F::T ; F_args::Tuple = (), F_kwargs::Dict = Dict(), alpha::Float64 = 0.5, m::Int64 = 5, X::Vector = [], G::Vector = [], max_cond::Float64 = 1e10, restart::Float64 = 1.0, _extra...) --> Dict where {T<:Function, N<:Union{Number, Vector{<:Number}}}

Anderson (Pulay / DIIS) mixing with history depth m. With residual g = VOut - VIn, the next input is

VInNext = VIn + alpha * g - (ΔX + alpha * ΔG) * γ,     γ = argmin ‖g - ΔG γ‖,

where the columns of ΔX and ΔG are differences of the last m + 1 inputs and residuals. Costs O(N m²) per iteration and O(N m) memory, so it suits large inputs. m = 0 is exactly SimpleMixing.

Two safeguards:

  • If the least-squares problem becomes ill-conditioned (condition number above max_cond), the oldest history entries are dropped.
  • If the residual grows, ‖g‖ > restart * ‖g_previous‖, the history is cleared and the step falls back to simple mixing. Stale history from a different nonlinear regime otherwise steers the extrapolation wrong, and a longer history makes it worse. Pass restart = Inf to disable.

Returns a dictionary containing the following

  • "VInNext" : the Anderson-extrapolated next input.
  • "VOutNext" : The function F evaluated at VInNext, with fixed args F_args and kwargs F_kwargs.
  • "Delta" : The maximum absolute per-component difference b/w the next input and output.
  • "kwargs" : the kwargs of this function itself, including the input history X and residual history G for the next iteration.

FixedPointToolkit.Updates.BroydenMixing — Method
BroydenMixing(VIn::N, VOut::N, F::T ; F_args::Tuple = (), F_kwargs::Dict = Dict() , alpha::Float64 = 0.5, B::Z = alpha*Matrix(1.0I, length(VIn), length(VIn)), _extra...) --> Dict where {T<:Function, N<:Union{Number, Vector{<:Number}}, Z<:Union{Number,Matrix{<:Number}}}

Quasi-Newton ("good" Broyden) update. With residual g = VOut - VIn, the next input is VIn + B * g, where B approximates -J⁻¹ for the Jacobian J of g. The initial B = alpha * I is exactly simple mixing with weight alpha; afterwards B is improved by a rank-1 secant update every iteration (O(N²) work and memory).

Returns a dictionary containing the following

  • "VInNext" : VIn + B * (VOut - VIn).
  • "VOutNext" : The function F evaluated at VInNExt, with fixed args F_args and kwargs F_kwargs.
  • "Delta" : The maximum absolute per-component difference b/w the next input and output, so convergence requires every component (not just the aggregate) to be within tol.
  • "kwargs" : the kwargs of this function itself, to be used by a subsequent function call in the next fixed point iteration. Here, the B-matrix is updated every iteration according to Broyden mixing rules.
Note

Before v1.2 the step was VIn - B * (VOut - VIn), so the default B = alpha * I initially stepped away from the fixed point. A B matrix saved in a checkpoint by an older version has the opposite sign convention.

Hot to write your own Update

If you want to design your own update function, you need to follow certain guidelines

  • Define your function as follows (F is the function whose fixed point is being calculated)
function CustomUpdate(VIn::N, VOut::N, F::T ; F_args::Tuple = (), F_kwargs::Dict = Dict(), kwargs..., _extra...) :: Dict where {T<:Function, N<:Union{Number, Vector{<:Number}}}
    ##### Get VInNext by doing something on VIn, VOut, and stuff in kwargs.
    VOutNext    =   F(VInNext, F_args... ; F_kwargs...)

    ##### If you want to include scheduling, you can now include a function which updates the kwargs themselves --> call then new_kwargs (MUST contain all the keys of kwargs, even if they are unchanged)

    return Dict("VInNext"   => VInNext, 
                "VOutNext"  => VOutNext,
                "Delta"     => norm(VOutNext - VInNext) / sqrt(length(VInNext)), 
                "kwargs"    => new_kwargs)
end
  • Every other argument you pass to your CustomUpdate must be a keyword argument.
  • Unlike CustomScheduler, you will be able to pass whatever kwargs you want to CustomUpdate when you begin the Fixed Point iterations..

Choosing an update method

In a real self-consistency loop the cost is dominated by calls to F, so what matters is how many iterations a method needs. The table below (from Sample/MixingComparison.jl) gives the number of F calls needed to reach max|F(x) - x| < 1e-8 on standard test problems; "–" means not converged within 2000 iterations.

Nonlinear map with spectrum in [-0.9, 0.97], N = 60132453834
Complex linear map, N = 40112457162
  • AndersonMixing is the recommended default when F is expensive. It stores only m past steps (O(N m) memory). Stiff, nearly linear problems benefit from a longer history m.
  • BroydenMixing is robust and remembers all past steps, but it stores a dense N×N matrix, so it suits N up to a few thousand.
  • SimpleMixing is enough when F is cheap and the iteration is already a good contraction.
